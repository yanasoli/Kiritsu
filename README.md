# Kiritsu / SkillUp

Веб-приложение для развития реальных навыков. Kiritsu — имя репозитория,
SkillUp — временное имя интерфейса.

Текущий этап: регистрация, подтверждение почты, вход, защищённая страница и выход.
Задания, XP, ИИ и подписки пока не реализованы.

## 1. Запуск

Нужны Node.js 24 LTS и pnpm 11 (в текущем окружении они доступны).
Команды выполняются в PowerShell из `D:\Kiritsu`:

```powershell
pnpm install
Copy-Item .env.example .env.local
pnpm dev
```

Открой http://localhost:3000. Интерфейс доступен и без Supabase, но регистрация
сообщит о недостающих настройках. Пользователи локально не создаются.
Если `.env.local` уже есть, не перезаписывай его командой копирования.

## 2. Подключение Supabase

1. Открой https://supabase.com/dashboard и создай проект (New project).
   Выбери регион и надёжный пароль базы. Пароль базы приложению не нужен.
2. Дождись готовности проекта. В Connect найди **Project URL** и
   **Publishable key** (`sb_publishable_…`). Названия разделов могут меняться;
   также смотри Project Settings → API Keys.
3. Заполни `.env.local`:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_your_public_key
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

4. В Authentication → Sign In / Providers включи Email и оставь подтверждение
   email включённым. Минимальная длина пароля — 8 символов, как в приложении.
5. В Authentication → URL Configuration укажи Site URL:
   `http://localhost:3000`, добавь Redirect URL:
   `http://localhost:3000/auth/confirm`.
6. В Authentication → Email Templates → Confirm signup замени ссылку
   подтверждения на:

```html
<h2>Подтверди регистрацию в SkillUp</h2>
<p><a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email">Подтвердить почту</a></p>
```

Обработчик проверит одноразовый `token_hash` на сервере и создаст сессию.
Так письмо можно открыть и в другом браузере. Обработчик также поддерживает
PKCE-код, но для предсказуемого потока используй шаблон выше.

7. Перезапусти сервер: `Ctrl+C`, затем `pnpm dev`.
8. Зарегистрируй свою почту, открой письмо, подтверди адрес.
   Ты попадёшь на `/dashboard`. Проверь выход и повторный вход.
   Пользователя можно увидеть в Authentication → Users.

Пользователи и хеши паролей хранятся в управляемой Supabase схеме `auth` в
PostgreSQL. SQL-миграция и отдельная таблица `profiles` на этом этапе не нужны.

`Publishable key` предназначен для публичного приложения. `secret`,
`service_role`, пароль базы и будущий OpenAI API key не должны попадать в
`NEXT_PUBLIC_*`, Git или клиентский код. `.env.local` исключён из Git.
Для подключения Supabase здесь не нужны административные ключи.

Если письмо не приходит: проверь Spam, Authentication → Logs и настройки
почтового сервиса. Встроенная отправка Supabase имеет ограничения;
для публичного запуска нужно настроить собственный SMTP.

## 3. Как устроен код

```text
src/
  app/
    layout.tsx            Общий HTML, язык страницы и метаданные
    globals.css           Tailwind и общий визуальный стиль
    page.tsx              Переход с / на /register
    register/page.tsx     Регистрация
    login/page.tsx        Вход
    auth/confirm/route.ts Подтверждение почты и создание сессии
    dashboard/page.tsx    Приветствие; серверная проверка пользователя
    error.tsx            Восстановление после ошибки загрузки
    not-found.tsx        Страница 404
  components/
    brand.tsx            Логотип
    auth-shell.tsx       Общая оболочка страниц регистрации и входа
  features/auth/
    auth-form.tsx        Клиентская форма, ошибки, состояние отправки
    validation.ts       Общие правила Zod для браузера и сервера
    actions.ts          Серверные действия регистрации, входа и выхода
    session.ts          Получение подтверждённого пользователя
  lib/supabase/
    config.ts           Чтение публичных настроек
    server.ts           Supabase-клиент для серверного кода и cookies
  proxy.ts              Обновление сессии перед обработкой запроса
tests/
  auth-validation.test.ts
```

`page.tsx` создаёт маршрут App Router. Страницы по умолчанию серверные.
`"use client"` нужен форме для интерактивности. `"use server"` означает,
что действия выполняются на сервере; проверку данных всё равно повторяем там.
Проверка в браузере помогает человеку, серверная проверка защищает приложение.

Поток: форма → Server Action → Supabase Auth → cookies → `/dashboard`.
Защита страницы проверяет пользователя через `getUser()`, а не наличие cookie.
`proxy.ts` обновляет токены, но не заменяет проверку прав в защищённом коде.
Будущие запросы к навыкам также должны проверять пользователя и иметь RLS.

## 4. Выбор технологий

- **Next.js + React + TypeScript**: страницы и серверный код в одном проекте,
  типы между модулями. Компромисс: надо понимать границу сервера и браузера.
- **Tailwind CSS 4**: единые стили без UI-фреймворка. Повторяемые элементы
  пока оформлены общими CSS-классами, чтобы код формы легче читался.
- **Supabase Auth + PostgreSQL**: готовая работа с паролями, письмами и сессиями,
  стандартная SQL-база для будущих функций. Компромисс: зависимость от сервиса,
  его тарифов, доставки писем и настроек доступа.
- **Zod**: одна схема проверки данных для браузера и сервера.
- **pnpm**: доступен в этом окружении; `pnpm-lock.yaml` фиксирует зависимости.

Для `dev` и `build` выбран поддерживаемый флаг `--webpack`: Turbopack в текущем
Windows-окружении завершился внутренней ошибкой при обработке CSS. Webpack
успешно собирает приложение; архитектуру Next.js это не меняет.

Отдельные Express/Nest backend, Prisma, Redux и микросервисы сейчас не нужны.
Vite с отдельным backend тоже подойдёт, но добавит настройку API и сессий.
Vercel можно подключить позже; текущий Next.js запускается и как Node-сервер.
OpenAI API добавим только в серверный код на отдельном этапе.

## 5. Проверки

```powershell
pnpm typecheck
pnpm test
pnpm build
```

После подключения Supabase вручную проверь:

- Неверный email, короткий пароль, несовпадение паролей показывают ошибки.
- Успешная регистрация отправляет письмо; вход до подтверждения отклоняется.
- Подтверждение открывает `/dashboard`, а перезагрузка сохраняет сессию.
- Вход с неверным паролем даёт общую ошибку, без раскрытия существования email.
- Повторная регистрация не раскрывает наличие аккаунта.
- Выход переводит на `/login`; `/dashboard` в новой вкладке также отправляет на вход.
- Просроченная или повторно использованная ссылка показывает ошибку.

Модульные тесты проверяют валидацию, но не доказывают работу внешнего Auth.
Реальный сценарий регистрации можно проверить только с настроенным Supabase.

## 6. Перед публичным запуском

Установи production URL и адрес подтверждения в Supabase и переменных
окружения платформы. Настрой SMTP, ограничения запросов и защиту от ботов в
Supabase Auth, восстановление пароля, документы о приватности. Для будущих
публичных таблиц добавляй RLS до использования клиентского доступа.
Сейчас проект предназначен для локального первого этапа.

Официальные источники:
[Next.js](https://nextjs.org/docs/app/getting-started/installation),
[Supabase SSR](https://supabase.com/docs/guides/auth/server-side/creating-a-client),
[Email и пароль](https://supabase.com/docs/guides/auth/passwords).
